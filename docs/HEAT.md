# 열섬 위험 지수 (발표·설명용)

`web/js/heat.js` 에서 브라우저가 직접 계산합니다. 외부 API 없이 **V-World 건물 + 연속지적도**만 사용.

## 계산 (11/10 위성 보정)
5m 격자 칸마다, **주변 반경 50m(10칸) 평균**으로 "여름 한낮 지표온도가 무실동 평균보다 몇 °C 높은지"를 추정:

```
추정 °C = 4.0 × 포장면 비율   (도로·인도·대지·건물 지붕)
        + 17.4 × 건물 덮개 비율
        − 21.8 × 건물 높이(8칸=40m 이상이면 1)   ← 고층 단지는 그늘·조경으로 덜 뜨거움
        − 4.6 × 녹지 비율     (공원·임야 1, 밭·풀밭 0.6)
        − 3.0 × 수면 비율     (하천·구거)
지수 = 추정 °C 를 −4.6°C → 0점, +8.4°C → 100점으로 직선 변환  (10점 ≈ 1.3°C)
```

| 점수 | 단계 |
|---|---|
| 85+ | 매우 높음 |
| 70~84 | 높음 |
| 45~69 | 보통 |
| ~44 | 낮음 |

## 위성 지표온도 보정 (근거)
- 자료: **Landsat 8·9 Collection 2 Level-2 표면온도(ST_B10)**, 무실동이 맑은 여름 5장면
  (2023-06-17, 2024-06-03, 2024-06-11, 2024-08-14, 2025-06-22). Microsoft Planetary Computer에서 키 없이 받음
- 재현: `python data/fetch_lst.py` → `data/raw/muksil_lst.tif`, `python data/calibrate_lst.py` → 아래 숫자
- 대시보드 그림: `python data/export_lst.py` → `web/data/lst_compare.json` (100m 구역별 지수·위성 온도, 바닥 종류별 온도). 파일이 없으면 대시보드는 아래 숫자만 보여줌
- 장면마다 무실동 평균과의 차이(°C)를 구해 평균 → 지도 5m 격자로 맞춘 뒤 30m·100m 구역 평균으로 비교
- **결과**

| | 30m 구역 | 100m 구역 |
|---|---|---|
| 예전 가중치(가정값) 지수 vs 위성 | r = 0.81 | r = 0.83 |
| **보정한 가중치** 지수 vs 위성 | **r = 0.86** | **r = 0.88** |

- 바닥 종류별 위성 온도(무실동 평균 대비): 저층 건물 +4.1, 중층 +4.5, **고층(40m+) +2.8**, 차도 +2.6, 인도·대지 +3.3, **공원·숲 −3.3**, 잔디·밭 +0.1, 하천 +0.4°C
  - **지붕이 도로보다 뜨겁고, 고층 단지는 저층보다 덜 뜨거움** → 예전 가정(도로 최대, 높을수록 뜨거움)을 고침
  - 하천은 폭이 좁아 열 센서(100m)로는 효과가 거의 안 잡힘 → 맞춤값은 0이지만, 쿨링포그 제안 효과를 위해 문헌 수준의 작은 값(−3°C)을 둠
  - 포장면도 맞춤에서는 0에 가깝게 나오지만(지붕과 함께 움직여서 구분이 어려움), 그늘막·투수포장 제안 효과를 위해 4°C로 고정
- **한계**: 땅 **표면** 온도(오전 10시 반 촬영)이지 **기온**이 아님. 화면 문구도 "땅 표면 … (위성 보정)"으로 표시

발표 멘트: "처음엔 연구 경향으로 만든 가정값이었는데, 위성 지표온도 5장면과 맞춰 가중치를 보정했고 상관이 0.88입니다.
위성으로 보니 지붕이 도로보다 뜨겁고 고층 단지는 오히려 덜 뜨거웠습니다."

## 시민 제안 시뮬레이션 (완료)
- 제안 유형마다 효과(녹지·수분·포장면·지붕)와 영향 범위가 정해져 있음 (`types.js` 의 `effect`)
- 위치를 누르고 유형을 고르면 **"놓으면 이 주변 지수 46 → 37 (−9)"** 미리보기 + 초록 사각형으로 영향 범위 표시
- `✨ 제안 효과` 버튼: 지금까지 모든 시민 개선 제안이 실현됐을 때의 열섬 지도로 바꿔 그림
- 리포트 패널: **영향권**(지수가 0.5 이상 내려간 곳)의 면적과 평균 변화. 무실동 전체 평균은 면적이 커서 변화가 묻히므로 영향권 기준으로 말함

## 우선 개선 구역 (대시보드)
- 서버(`backend/heatmodel.py`)가 같은 열섬 계산을 numpy로 다시 함 (웹과 결과 동일함을 확인). **두 파일 중 하나를 고치면 다른 쪽도 같이.**
- 200m 구역마다: **점수 = 0.6 × 열섬 지수(구역 평균) + 0.4 × 100 × √(시민 요구 / 최대 요구)**
  - 예전엔 상위 10% 칸을 썼으나, 지수가 100에서 잘려 시가지 구역 6곳이 100으로 동점 → 순서가 임의로 정해지는 문제가 있어 평균으로 변경(11/09). 시민 페이지 TOP 3(구역 평균)과 같은 기준.
  - 상위 10% 값(`heat_p90`)은 참고용으로 표에만 남김
  - 시민 요구 = 개선 제안 + 불편 신고 + 공감/2
  - 숲·밭만 있고 요구도 없는 구역은 제외
- "실현 시" = 그 구역의 시민 개선 제안이 모두 시행됐을 때의 구역 평균 지수 (시뮬레이션)
- AI 정책 제안: TOP 3 구역 자료(열섬 지수, 토지 구성 = 포장면·건물·녹지 비율, 시민 요청)만 주고 "자료에 있는 숫자만, 자료에 없는 원인(교통량 등)은 추측 금지"로 지시 (Bedrock). 실패 시 규칙 기반 문장

## 실시간 지수 읽기 + 추정 지표온도
- 열섬 지도를 켜면 **PC는 마우스 아래**, **폰은 화면 가운데 십자** 위치의 지수가 바로 떠요 (`app.js` `updateProbe`).
- **여름 한낮 지표온도 차이 = −4.6 + 지수 × 0.13 °C** (`heat.js` `tempOffset`, 위 보정과 같은 식) → 무실동 평균 지수(약 36점)가 0°C.
  화면: "여름 한낮 땅 표면이 동네 평균보다 약 +3.1°C (위성 보정)". 지금 기온에 더하지 않음(지수는 여름철 열 축적).
