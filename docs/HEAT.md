# 열섬 위험 지수 (발표·설명용)

`web/js/heat.js` 에서 브라우저가 직접 계산합니다. 외부 API 없이 **V-World 건물 + 연속지적도**만 사용.

## 계산
5m 격자 칸마다, **주변 반경 50m(10칸) 평균**으로:

```
원점수 = 0.45 × 포장면 비율   (도로·인도·대지·건물 지붕)
       + 0.20 × 건물 덮개 비율
       + 0.15 × 건물 높이(8칸=40m 이상이면 1)
       − 0.45 × 녹지 비율     (공원·임야 1, 밭·풀밭 0.6)
       − 0.30 × 수면 비율     (하천·구거)
```
원점수를 0~100점으로 펼침 (시가지 값이 몰린 0.15~0.55 구간을 40~100점으로 넓게).

| 점수 | 단계 |
|---|---|
| 85+ | 매우 높음 |
| 70~84 | 높음 |
| 45~69 | 보통 |
| ~44 | 낮음 |

## 근거 (발표 멘트)
- 도시 지표면 온도는 **불투수면(포장·지붕) 비율이 높을수록 올라가고**, **녹지·수면 비율이 높을수록 내려간다**는 관계가 국내외 연구에서 반복적으로 보고됨.
- 고층·고밀 건물은 바람길을 막고 밤에 열이 빠져나가지 못하게 함.
- 이 지수는 **PoC용 단순 모델**. 다음 단계로 위성 지표온도(Landsat 열적외선)·기상청 기온으로 가중치를 보정할 수 있음.

## 시민 제안 시뮬레이션 (완료)
- 제안 유형마다 효과(녹지·수분·포장면·지붕)와 영향 범위가 정해져 있음 (`types.js` 의 `effect`)
- 위치를 누르고 유형을 고르면 **"놓으면 이 주변 지수 46 → 37 (−9)"** 미리보기 + 초록 사각형으로 영향 범위 표시
- `✨ 제안 효과` 버튼: 지금까지 모든 시민 개선 제안이 실현됐을 때의 열섬 지도로 바꿔 그림
- 리포트 패널: **영향권**(지수가 0.5 이상 내려간 곳)의 면적과 평균 변화. 무실동 전체 평균은 면적이 커서 변화가 묻히므로 영향권 기준으로 말함

## 우선 개선 구역 (대시보드)
- 서버(`backend/heatmodel.py`)가 같은 열섬 계산을 numpy로 다시 함 (웹과 결과 동일함을 확인). **두 파일 중 하나를 고치면 다른 쪽도 같이.**
- 200m 구역마다: **점수 = 0.6 × 열섬 지수(구역 평균) + 0.4 × 100 × √(시민 요구 / 최대 요구)**
  - 예전엔 상위 10% 칸을 썼으나, 지수가 100에서 잘려 시가지 구역 6곳이 100으로 동점 → 순서가 임의로 정해지는 문제가 있어 평균으로 변경(11/09). 시민 페이지 TOP 3(구역 평균)과 같은 기준.
  - 상위 10% 값(`heat_p90`)은 참고용으로 표에만 남김
  - 시민 요구 = 개선 제안 + 불편 신고 + 공감/2
  - 숲·밭만 있고 요구도 없는 구역은 제외
- "실현 시" = 그 구역의 시민 개선 제안이 모두 시행됐을 때의 구역 평균 지수 (시뮬레이션)
- AI 정책 제안: TOP 3 구역 자료(열섬 지수, 토지 구성 = 포장면·건물·녹지 비율, 시민 요청)만 주고 "자료에 있는 숫자만, 자료에 없는 원인(교통량 등)은 추측 금지"로 지시 (Bedrock). 실패 시 규칙 기반 문장

## 실시간 지수 읽기 + 추정 기온
- 열섬 지도를 켜면 **PC는 마우스 아래**, **폰은 화면 가운데 십자** 위치의 지수가 바로 떠요 (`app.js` `updateProbe`).
- **여름 한낮 기준 차이 = (지수 − 50) × 0.06°C**  → 0점 −3°C, 100점 +3°C. 화면: "여름 한낮엔 보통 지역보다 약 +1.8°C (추정)".
  지금 기온에 더하지 않음(11/09 변경): 지수는 여름철 열 축적을 뜻하는데, 겨울 현재 기온에 더하면 계절이 맞지 않음.
  도시 열섬 강도(도심과 녹지의 기온 차)가 보통 수 °C 수준이라는 문헌값에 맞춘 **PoC 가정**. 실측값이 아니므로 화면에도 "추정"이라고 표시함.
  발표 멘트: "같은 무실동 안에서도 아파트 단지 한가운데와 공원은 여름에 수 도 차이가 날 수 있다는 걸 보여주는 지표"
